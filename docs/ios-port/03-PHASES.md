# 03: Ordered port phases

The order is chosen so that **a usable app exists after P6**, analyzed by the server and played on
the device, and the hardest, riskiest port (on-device analysis, P7) lands on a proven engine with
its oracles already in place. Every phase ends on a gate command whose output is the evidence.

Gate commands:
- PC: `python tools/ios-parity/run_oracles.py --check` and `node tools/ios-parity/js/trace.mjs --check`
- mini: `cd ~/Developer/HarmonizerMobile && tools/verify.sh`. This runs lint → xcodegen → `swift
  test` for each package → `xcodebuild test` on a simulator **addressed by UDID**, with
  `set -o pipefail` and `PIPESTATUS` checked.

---

### P0: Oracles and fixtures (PC, `harmonizer/tools/ios-parity/`, test tooling only)

1. **Pin the reference environment.** Read the prod versions with tier-3 (`keysafe run
   harmonizer-admin` → `docker exec harmonizer pip freeze`). Tier-1 cannot reach the docker socket.
   If that is unavailable, pin to the PC's current set (librosa 0.11.0, numpy 1.26.4, scipy 1.16.2,
   soundfile 0.13.1, libsndfile 1.2.2, sklearn 1.7.2) and record the gap in `ORACLE_ENV.md`. Write
   `requirements-oracle.txt` with `==` pins and use a dedicated venv.
2. **Fixture corpus** (`fixtures/audio/`, FLAC, size budget ≤ 40 MB in git):
   - Synthetic, generated by `gen_synthetic.py`, deterministic: a 120 bpm click+chord loop; a
     97 bpm swing; a tempo ramp 100→130; a 3/4 waltz; silence-heavy intro/outro; mono; and 22.05,
     44.1, and 48 kHz variants.
   - Real: 3 CC0/CC-BY tracks (pop, acoustic, electronic, 3–6 min) with their license in
     `fixtures/LICENSES.md`.
   - Optional private user tracks referenced by hash only. They are never committed.
3. **Python layered dumper** `dump_layers.py`. It imports `backend/analysis/analyze_track.py`
   functions **without modifying them** and writes, per fixture, `layers/<id>/<stage>.f32` (LE
   float32 + `.json` shape header) for: pcm_mono hash, stft_mag (first 200 frames), rms, mfcc13,
   mfcc20, delta, onset_env, tempo + beat_frames, chroma, segments, sections, beat_features_91,
   canon_ssm, offset_candidates, canon_alignment, eternal_ssm (blocked), eternal_loop_candidates,
   canon_candidates, global_voice_offsets. It also writes the full `profile.json` via
   `build_profile`.
4. **JS live-engine trace harness** `js/trace.mjs` (Node + jsdom). It loads `jquery-3.7.1.min.js`,
   `underscore-min.js`, a Raphael **stub**, `jremix.js`, and `visualizer.js` with:
   - a fake `AudioContext` (nodes are no-ops; `currentTime` comes from a virtual clock);
   - `setTimeout`/`setInterval`/`Date.now`/`performance.now` on the virtual clock (a timeout
     advances the clock and runs immediately);
   - `Math.random` = **Mulberry32(seed)**, **re-seeded right after `getPlayer()` returns**. That
     isolates the impulse-response and vinyl-noise draws made at player construction.
   - `window.mode`, `window.canonVoiceCount`, `harmonizerBaseAudioOnly=false`,
     `harmonizerRLModel` (none / empty / fixture GBRT), and settings injected.
   - `playQ` wrapped to record each tick: `{tick, mainBeat, mainRestart, voices:[{beat, restart,
     offset}], rate, draws}`.
   Outputs: `traces/<fixture>/<mode>-v<voices>-<policy>-s<seed>.jsonl` (5,000 ticks) and
   `prep/<fixture>.json`, which holds neighbors, goodNeighbors, loopGraph, `q.other`/`others`,
   gains, and voiceOffsets.
   *Fallback if visualizer.js will not load headless:* `extract_drivers.mjs` slices the driver and
   prep functions by line range into a module with explicit global shims. This is still the
   unmodified source text.
5. **Reference mixer** `ref_mix.py`. It turns a trace + PCM into the exact expected output samples
   under the native semantics (continuous read heads, restart on discontinuity, `declickMs=0`,
   no FX). This is the sample-level oracle for P4.

**Done when:** `run_oracles.py --check` and `trace.mjs --check` regenerate everything twice with
byte-identical hashes (`fixtures/MANIFEST.sha256`); traces exist for every fixture × {canon v2,
v3, v5, v8, jukebox, eternal, autocrooner} × {baseline, heuristic, gbrt} × 3 seeds; and
`ORACLE_ENV.md` records the versions.

### P1: iOS repo skeleton (mini)

`~/Developer/HarmonizerMobile`: `project.yml` (iOS 17.0, Swift 6, bundle
`com.ahmedsajid.harmonizer`, team `NEMJR674ZA`, `UIBackgroundModes: [audio]`), the four local SPM
packages from 01-ARCHITECTURE.md, `tools/verify.sh`, `tools/dead-control-lint.sh` (copied pattern
from HTVMobile), fixtures synced from the PC via `scp`, and `Fixtures/MANIFEST.sha256` verified in
a test.

**Done when:** `tools/verify.sh` is green with one placeholder test per package plus a manifest-hash
test, the app launches in the simulator, and `iosrun` captures a screenshot.

### P2: Profile model + graph prep (`HarmonizerCore`)

`Profile` Codable (tolerant: missing/null fields, string-keyed candidate maps), `TrackModel`, and
everything in 02-PORT-MAPPING §A1–A2, plus `ParityRNG` (Mulberry32, bit-identical to the harness).
First, settle FINDINGS 9 (whether alignment gain is consumed).

**Done when:** for every fixture profile, Swift prep output equals `prep/<fixture>.json`. Integers
and orderings must match exactly; floats within 1e-12 relative, since both sides are IEEE double.
Also, Mulberry32 matches the first 10,000 outputs of the JS generator for 3 seeds.

### P3: Decision engines (`HarmonizerCore/Engines`)

`VoiceBank` (playQ logic), `CanonDriver`, `JukeboxDriver` (jukebox + eternal), `AutoCroonerDriver`,
`RLScorer`, and `EngineFactory`. Port in this order: autocrooner (smallest, proves the trace
plumbing) → canon → jukebox → eternal deltas.

**Done when:** `TraceParityTests` replays every P0 trace. All 5,000 ticks are identical in mainBeat,
restart flags, voice beats/offsets, and RNG draw count, and rate is within 1e-12. A divergence is
accepted only if the harness shows it is a libm knife-edge (softmax pick margin < 1e-12), and each
accepted case is listed in `PARITY_EXCEPTIONS.md`.

### P4: Render engine (`HarmonizerAudio`)

`PCMStore`, the C `RenderKernel` (voices, read heads, interpolation, pans, biquads, gains, peak
guard, declick), `Scheduler` (lookahead SPSC ring, ~1 s), `OfflineRenderer`, then `CroonerFX`.

**Done when all of the following hold:**
- (a) the offline render of 3 traces per mode, with `declickMs=0` and no FX, matches `ref_mix.py`
  with max abs error ≤ 1e-6 and every jump landing at exactly `round(beat.start*sr)`;
- (b) FX component tests pass: biquad magnitude response vs the Web Audio formula within 0.1 dB at
  20 frequencies; the shaper equals `tanh(k·x)` within curve resolution; the compressor static curve
  is within 0.5 dB; the delay LFO depth and rate are as specified; and convolver normalization
  matches the spec's formula;
- (c) a 30-minute real-time soak on the simulator, *and* on device in P8, shows 0 underruns, kernel
  time < 25% of the buffer period at 5 ms IO buffers, and zero allocations on the render thread
  (Instruments allocations trace or a malloc-hook test).

### P5: Server client (`HarmonizerNet`)

Endpoints from 01-ARCHITECTURE.md: multipart `/api/process` (upload + URL sources), status polling
(1 s, 10-min cap, `cached` status), `/data/<id>.json` with no-store, `/media` range download with
resume, `/api/background-render` + status (1.2 s), `/api/rl/policy|model`, batched
`/api/rl/jump-event`, `/api/harmonizer/cloud/search`. Handle typed errors: 429 (rate limit, show
the reset), 401/403, 502/503, and job `failed`.

**Done when:** contract tests decode recorded real responses (captured once from
harmonizerlabs.cc into `Fixtures/http/`), and a live smoke test (`LIVE=1`, opt-in, **at most 1
`/api/process` call per run** because of the 6/hr limit) completes upload → profile → media using
a small CC0 fixture.

### P6: App shell, end to end with server analysis

SwiftUI: library (imported tracks: sourceHash, PCM file, profile in Application Support), import
(Files/share sheet), URL/cloud-search import via the server, a now-playing screen with a mode picker
(4 modes), canon voice slider 2–8, advanced settings sheets (defaults from §A2), a beat ring view
(circle of beats, current beat, voice markers, recent jump arcs, drawn with SwiftUI `Canvas`),
`AVAudioSession` + background audio + interruptions/route changes + Now Playing/remote commands.
Mode switch rebuilds the engine without re-analysis. Seed is shown in debug settings for replay.

**Done when:**
- a UI test drives import of a fixture → server analysis (stubbed in CI, live behind `LIVE=1`)
  → play each of the 4 modes for 20 s with the beat index advancing → screenshots via `iosrun`;
- `dead-control-lint` passes;
- background playback continues 60 s after the app is backgrounded in the simulator (asserted by
  scheduler tick count).

### P7: On-device analysis (`HarmonizerAnalysis`), staged by layer

Order: 7a decode/mono/STFT/RMS → 7b mel/MFCC/delta → 7c onset strength + `onset_detect` backtrack
→ 7d tempo + beat tracker → 7e CQT chroma + tuning → 7f segments/bars/tatums/key/loudness → 7g
Ward sections → 7h canon SSM + alignment + loop edges → 7i eternal SSM + candidates → 7j canon
candidates + global offsets → 7k profile assembly (`analysis.version = "ios-1.0"`).

Each sub-stage first passes **given the Python golden inputs to that stage** (isolates the error),
then end to end.

**Done when:**
- every layer tolerance in 04-TESTING.md §2 is met on all fixtures;
- the behavioral gate in §2.3 passes;
- a 5-minute track analyzes in < 5 s on the oldest supported test device (A14-class) or < 2 s on
  an Apple-silicon simulator, with peak memory < 300 MB.

### P8: Local-first wiring + hardening

The fallback tree in 01-ARCHITECTURE.md, ProfileCache keyed by (sourceHash, analyzerId), offline
mode, engine health monitor → thin-player offer, Export (offline render → AAC m4a via
`AVAudioFile`), RL model cache + opt-in telemetry queue, thermal-state handling, and a long-run
soak.

**Done when:**
- fallback-tree tests cover every branch, using an injected network and analyzer
  (airplane mode / 429 / analyzer disabled / over the beat cap / thermal critical);
- a 2-hour on-device soak in each mode shows no underruns, no memory growth > 10 MB, and
  battery/thermal recorded;
- export of 10 min in canon v4 completes and plays in Files.

### P9: Release (internal TestFlight)

App icon, `PrivacyInfo.xcprivacy` (file access; network only to harmonizerlabs.cc; no tracking),
audio-quality human gate on device (each mode vs the web page on the same track, side by side),
archive + upload from the **GUI** session (the SSH archive fails at codesign; see memory
`choralus-mobile-repo`).

**Done when:** build N is in internal TestFlight and the user has signed off on the human audio gate.
These are **hard stops needing the user**: GUI archive/upload and the listening sign-off.
